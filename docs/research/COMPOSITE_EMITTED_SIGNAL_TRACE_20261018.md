# Emitted-signal trace in the existing physical VAL-40 path

The previous composite producer retained aggregate performance and discarded its generated boolean signal mask. The independent Decimal fill oracle also returned only a pass/count summary. A later reviewer therefore could not match a specific emitted signal to the oracle entry, exit, or rejection from the stored producer artifact.

The existing default VAL-40 evaluator now captures the complete signal mask immediately after `signal_for`, before either cost-profile replay. It retains a source-commit/candidate/config identity, exact canonical dataset bindings (including a peer binding where used), a contiguous closed 15-minute clock, and an event ID for every true signal. Event IDs include a chained hash of the available decision-feature prefix; later feature/price changes do not change prior IDs. They are shared across the conservative and stress profiles. Whole-window dataset bindings remain in the containing capture; the ID alone is not provider authentication.

The existing independent fill oracle records every emitted signal's disposition, including occupied position, entry-bar rearm suppression, invalid stop, unavailable positive range, daily/drawdown halt and terminal censoring. Its BUY/SELL audit rows carry the same event ID. The production financial simulator and strategy equations are unchanged. The stored fill rows belong to the independent oracle; the financial producer still emits aggregates rather than its own fill ledger.

The existing producer artifact now uses `nexus.composite-runtime-requalification.v2` when both symbol traces are present. Its normal verifier checks both traces, complete signal/disposition coverage, next-open entry, paired exits, cost-profile fee arithmetic, per-trade net PnL and aggregate agreement. The physical workflow requires v2 for new executions. Old v1 receipts remain readable with their original limitations. A mixed/incomplete trace or a v1 envelope containing v2 traces is rejected. The existing independent QA path replays and compares the complete producer artifact, so it also consumes the traces; no parallel Manager/qualification pipeline was created.

A synthetic 3,072-bar, all-signals, same-bar-target stress case exceeded the previous 500-kB job-log transport limit. The physical publisher, hosted decoder and QA consumer now consistently allow a bounded 3,000,000-byte compressed payload, 96 fixed-size base64 chunks and a 12,000,000-byte JSON member. The existing 8-MB log/archive and 16-MB aggregate expansion limits remain. v2 output uses compact JSON to avoid nested indentation multiplying the payload. The test round-trips the full high-activity evidence through the actual job-log decoder and artifact parser.

# NEXUS — original portfolio-v3 native fill journaling and independent FIFO cash reconciliation (18 October 2026)

## Exact engineering result

The original `bybit_portfolio_search_v3.py` already **constructs and fills real simulated BTC/ETH portfolio weights** in one common long-only 500-USDT Spot cash account with next-open 4-hour execution. It previously returned aggregate fill counts/fees, turnover and max drawdown, but **no per-fill or closed-trade journal**. Thus repeated claims of "nine positions" from nine original buy/sell *fill events* were not supported by the core engine. There was also no independent exact cash/fee/realized-profit FIFO oracle against the original execution path.

This change **instruments the existing engine** with one optional keyword-only `fill_trace={}` argument to `exact_backtest`, default `None`; the legacy no-trace execution contract, fees, slippage, decisions, execution prices, scheduled masks, target weights, allocation, portfolio cash and returned metrics are unchanged. The trace is appended *inside* the original authentic buy/sell and terminal-liquidation loops, not from a separate signal or fill simulator. No hard stop is added or claimed: risk control is **diagnostic only** pending separate rigorous risk-policy review.

### Original engine tracing without modifying default behavior

- Native actual fill rows record original simulated next 4-hour open timestamp (or explicitly labeled last 4h **terminal close**), source bar opening timestamp, symbol, buy/sell, traded quantity, simulated execution price, fee, after-fill single-wallet cash, after-fill actual asset quantity and monotonic sequence.
- Observed 4h mark-to-market equity/cash/inventory tape, with its final mark reconciled to actual terminal liquidation.
- New research-only `research/portfolio_v3_original_fill_journal.py` independently FIFO-matches *the actual original engine's* native fills and allocates every entry/exit fee, commission and actual fill execution costs. Partial sells create separate **matched FIFO lot segments**, not an invented count of independent entry-order positions. It fails closed on short/oversold inventory, non-UTC/out-of-order fills, altered cash or asset quantities, incorrect fees, unreconciled realized profits, missing terminal liquidation, or divergent maximum drawdown versus the old engine.
- One manual `scripts/nexus_portfolio_v3_original_fill_audit.py` opt-in bridge verifies **six exact original Bybit Spot BTC/ETH 15m/1h/4h raw SHA** before source load, validates the original strict 4h UTC price grid, reuses exactly the frozen original v3 `b4e4a2c33304aec1` dual-rotation candidate, schedules, research wallet 500 and all three conservative/stress/severe economic profiles from merged #2720, and only the two previously documented 2025Q1 and Sept2023–July2026 continuous historical scopes. No optimizer, no alternate trade engine, no unreviewed live actions or Demo connection.

### Source-of-truth and strict boundaries

- Original `bybit_portfolio_search_v3.py` is lightly instrumented **only in its optional observability path**. Existing callers omit `fill_trace` and thus receive original results without additional source/journal requirements or changed execution behavior. The Git blob hash of the module necessarily changes after adding optional observability, which should update `execution_model_receipt().module_sha256`: **earlier financial evidence remains earlier immutable source evidence; do not replace its source hash with the new module hash**.
- The optional journal is **a research audit, not a production event-storage stream**. This is not changing the GitHub actions/watchdog use, runner or runtime database. Future integration to read-only desktop UI would require an explicit separately reviewed deployment.
- The FIFO matched lot count represents *accounting matches*, **not necessarily actual independent opened/closed strategy positions**; the original buy/sell event count is also not a trade count. Exit-month monthly tables are based on matched FIFO segment exit timestamps, not pre-filtered order signal counts.
- **No physical hard-stop loss, intrabar stop fill, guarantee of gap risk, capital circuit breaker, or real Paper/Demo exchange order** has been added to portfolio v3 in this change. The older 15m 2.5-USDT nominal downside sidecar is a separate research model and must not be incorrectly attributed to 4h portfolio-v3 allocation risk.
- No EMA/threshold tuning, new Elliott variant, Strategy Finder frontier reset, live Bybit execution or owner Laptop1 app/key/journal modifications. Source truth remains GitHub; `Live=false`, `paper_eligible=false`, `orders=0`. The prospective V117 window stays unchanged.

## Next decision

The meaningful next separate gate is **explicit causal portfolio risk policy** for the original engine, evaluated with a precommitted maximum **shared-cash portfolio drawdown** and no hindsight. A valid circuit breaker can observe a 4h bar **only after its close**, and any exit at the *next* executable open must accept possible worse gap/slippage. Research must test this as a different, explicitly versioned risk policy, preserving default old-v3 results and validating full FIFO cash conservation. Only truly future untouched data and independent QA can even consider a prospective Demo admission, not current historical positive P/L.
